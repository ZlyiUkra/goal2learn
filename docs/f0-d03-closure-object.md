# Замикання з об'єктом

Вісім варіантів однієї загадки про замикання й таймер. Усі приклади зібрано в пісочниці:
<https://claude.ai/artifact/4M6qF3yhEyRGvfpp7DVfUT>. Там код можна правити й запускати, а біля кожного рядка виводу
видно, коли його надруковано: поки виконувався скрипт чи вже з таймера. Кожен вивід нижче перевірено в Node.

## Що спільне для всіх варіантів

Функція `makeShower(total)` повертає функцію, яка ставить таймер, а колбек таймера друкує `total`. Три поняття,
на яких тримаються всі розбори:

- **Оточення** (environment record) - місце, де живуть змінні одного виклику функції чи одного блоку. Кожен виклик
  `makeShower` створює нове оточення з власним `total`.
- **Замикання** - функція разом із посиланням на оточення, у якому її створено (поле `[[Environment]]`). Функція
  тримає саме оточення, тобто змінні, а не знімок їхніх значень на момент створення.
- **Черга таймерів** - колбек `setTimeout(..., 0)` не виконується одразу. Він чекає, поки скрипт дійде до кінця
  й стек викликів спорожніє. Тому все, що скрипт робить після `show()`, відбувається раніше за друк.

## Вихідна загадка

```js
function makeShower(total) {
  return function () {
    setTimeout(function () {
      console.log("знімок:", total);
    }, 0);
  };
}
const show = makeShower(10);
makeShower(20);
makeShower(30);
show();
```

Вивід: `знімок: 10`.

Чому так:

1. `makeShower(10)` створює власне оточення, у якому `total` дорівнює 10. Повернута функція потрапляє в `show`
   і тримає саме це оточення.
2. `makeShower(20)` і `makeShower(30)` створюють ще два оточення, кожне зі своїм `total`. Функції, які вони
   повертають, ніде не збережено, тож на `show` ці виклики не впливають.
3. `show()` ставить колбек у чергу таймерів. Колбек спрацьовує після кінця скрипту й читає `total` зі свого
   оточення, тобто 10.

Висновок: кожен виклик `makeShower` має власний `total`. Пізніші виклики не перезаписують змінну з раннього.

## Об'єкт: змінюємо вміст

```js
function makeShower(total) {
  return function () {
    setTimeout(function () {
      console.log("знімок:", total);
    }, 0);
  };
}
const box = { sum: 10 };
const show = makeShower(box);
box.sum = 20;
makeShower({ sum: 30 });
show();
box.sum = 40;
```

Вивід: `знімок: { sum: 40 }`.

Чому так:

1. `makeShower(box)` кладе в `total` посилання на об'єкт. Тепер `box` і `total` вказують на один і той самий
   об'єкт, копії не створюється.
2. `box.sum = 20` змінює цей спільний об'єкт. Змінну `total` ніхто не чіпає, вона й далі вказує туди ж.
3. `makeShower({ sum: 30 })` працює з іншим об'єктом в іншому оточенні й на `show` не впливає.
4. `show()` лише ставить колбек у чергу. Рядок `box.sum = 40` виконується раніше за колбек, бо таймер чекає
   кінця скрипту навіть із затримкою 0.
5. Колбек читає `total` після всього цього й бачить `{ sum: 40 }`.

Висновок: замикання тримає змінну `total`, а не копію її вмісту. Якщо в змінній посилання на об'єкт, колбек
побачить усі зміни цього об'єкта, зроблені до спрацювання таймера.

Типові відповіді на цю загадку:

- "10" - неправильно. Хибна думка: замикання запам'ятовує значення на момент створення.
- "30" - неправильно. Хибна думка: останній виклик `makeShower` перезаписує `total`.
- "20" - неочевидна відповідь. Мутацію враховано, але `show()` вважають миттєвим друком і забувають про таймер.
- "40" - правильно.

## Об'єкт: нова змінна

```js
function makeShower(total) {
  return function () {
    setTimeout(function () {
      console.log("знімок:", total);
    }, 0);
  };
}
let box = { sum: 10 };
const show = makeShower(box);
box = { sum: 99 };
show();
```

Вивід: `знімок: { sum: 10 }`.

Чому так:

1. `makeShower(box)` кладе в `total` посилання на перший об'єкт `{ sum: 10 }`.
2. `box = { sum: 99 }` змінює лише змінну `box`: тепер вона вказує на новий об'єкт. `total` - окрема змінна, і
   вона досі вказує на перший.
3. Колбек друкує той об'єкт, на який вказує `total`, тобто `{ sum: 10 }`.

Висновок: замикання бачить зміни вмісту об'єкта, але не бачить, що зовнішню змінну направили на інший об'єкт.

## Число: нова змінна

```js
function makeShower(total) {
  return function () {
    setTimeout(function () {
      console.log("знімок:", total);
    }, 0);
  };
}
let n = 10;
const show = makeShower(n);
n = 20;
show();
```

Вивід: `знімок: 10`.

Чому так:

1. `makeShower(n)` копіює в `total` число 10. Після цього між `n` і `total` немає жодного зв'язку.
2. `n = 20` змінює лише `n`.
3. Колбек читає `total` і друкує 10.

Висновок: число передається копією. Хоч би що потім сталося із зовнішньою змінною, `total` лишається 10.

## with: перекриття імені

Тут змінено саму функцію: колбек створюється всередині блоку `with (env)`.

```js
const env = {};
function makeShower(total) {
  return function () {
    with (env) {
      setTimeout(function () {
        console.log("знімок:", total);
      }, 0);
    }
  };
}
const show = makeShower(10);
makeShower(20);
makeShower(30);
show();
env.total = 40;
```

Вивід: `знімок: 40`.

Чому так:

1. `show()` заходить у блок `with (env)`. Блок ставить на початок ланцюжка пошуку оточення-об'єкт: ім'я спершу
   шукається серед властивостей `env`, а вже потім серед параметрів виклику `makeShower(10)`.
2. Колбек створюється всередині блоку й тримає саме цей ланцюжок, хоча сам блок закінчується одразу.
3. `env.total = 40` виконується синхронно, тобто раніше за колбек.
4. Коли таймер спрацьовує, колбек шукає `total`. Перевірка `"total" in env` тепер дає `true`, тож пошук
   зупиняється на `env.total`, і параметр зі значенням 10 до виводу не доходить.

Висновок: параметр не змінюється, його перекриває ім'я, яке стоїть у ланцюжку раніше. Пошук іде в момент
читання, тому важить лише те, що лежить в `env`, коли спрацьовує таймер.

Межові випадки:

- Без рядка `env.total = 40` вийде 10: в `env` немає `total`, і пошук доходить до параметра.
- Перевіряється весь ланцюжок прототипів `env`, а не лише власні властивості. Тому `with ({})` перекрив би
  параметр з іменем `toString` чи `constructor` методами з `Object.prototype`. А рядок
  `Object.prototype.total = 1` перекрив би параметр навіть без `env.total`.
- Через `env` спершу шукаються й `setTimeout` та `console`. Присвоєння `env.console = ...` до виклику `show()`
  підмінить `console`, після виклику - лише `console` усередині колбека.
- Імена з `env[Symbol.unscopables]` оточення-об'єкт пропускає. Так `Array.prototype` ховає свої новіші методи
  від старого коду з `with`.
- У strict mode `with` - помилка ще на етапі розбору: `SyntaxError: Strict mode code may not include a with
  statement`. Тому в модулях ES, класах і файлах з `"use strict"` цей код не запуститься. У консолі браузера й у
  звичайному скрипті Node він працює.

## call, apply, bind: аргумент

`call`, `apply` і `bind` самі до змінної замикання не дістаються: вони керують лише `this` і аргументами. Тому
функції потрібні "двері". У цьому варіанті ними є параметр `next`.

```js
function makeShower(total) {
  return function (next) {
    if (next !== undefined) total = next;
    setTimeout(function () {
      console.log("знімок:", total);
    }, 0);
  };
}
const show = makeShower(10);
show.call(null, 20);
show.apply(null, [30]);
show.bind(null, 40)();
show.bind(null, 40)(50);
```

Вивід - чотири рази `знімок: 40`.

Чому так:

1. Повернута функція приймає параметр `next` і, якщо його передано, присвоює його `total`. Це та сама змінна з
   оточення виклику `makeShower(10)`, а не копія.
2. `call`, `apply` і `bind` відрізняються лише способом передати аргументи. Перший аргумент кожного з них -
   `this`, тут він не потрібен, тому `null`. `call` бере аргументи списком, `apply` - масивом, а `bind` повертає
   нову функцію, у якій аргумент уже підставлено.
3. Кожен виклик ставить колбек у чергу й одразу змінює `total`: спершу на 20, потім на 30, потім на 40 і в
   останньому рядку ще раз на 40.
4. В останньому рядку `total` стає 40, а не 50, бо аргументи з `bind` стоять першими:
   `show.bind(null, 40)(50)` передає `next = 40`, а 50 потрапляє лише в `arguments[1]`, яке функція не читає.
5. Усі чотири колбеки спрацьовують після кінця скрипту й читають ту саму змінну `total`, у якій на той момент
   лежить 40.

Висновок: змінює `total` рядок `total = next` усередині функції, і ця зміна спільна для всіх колбеків цього
замикання. Ось тут `total` справді змінюється, а не перекривається.

Межові випадки:

- Зміна лишається назавжди: кожен наступний виклик `show()` без аргументу друкуватиме 40. Інших замикань, тобто
  функцій з інших викликів `makeShower`, вона не зачіпає.
- Через перевірку `next !== undefined` повернути в `total` значення `undefined` не вийде: `show(undefined)`
  нічого не змінить.
- `makeShower.bind(null, 40)` - інша річ. Це часткове застосування: виклик зв'язаної функції створить нове
  замикання з `total = 40`, а наявна `show` лишиться як була.

## call, apply, bind: this

Другий спосіб відчинити двері - `with (this)`. Тоді `call`, `apply` і `bind` передають об'єкт через `this`.

```js
function makeShower(total) {
  return function () {
    with (this) {
      setTimeout(function () {
        console.log("знімок:", total);
      }, 0);
    }
  };
}
const show = makeShower(10);
show.call({ total: 20 });
show.apply({ total: 30 });
show.bind({ total: 40 })();
show.bind({ total: 40 }).call({ total: 50 });
```

Вивід: `знімок: 20`, `знімок: 30`, `знімок: 40`, `знімок: 40`.

Чому так:

1. Замість спільного `env` блок `with` бере об'єкт із `this`, а `this` задають саме `call`, `apply` і `bind`.
2. Кожен виклик має власний об'єкт, тож кожен колбек тримає свій ланцюжок: перший знаходить `total` зі значенням
   20, другий - 30, третій - 40.
3. Сама змінна `total` у замиканні не змінюється. Її перекриває властивість об'єкта, як у варіанті з `env`.
4. `this`, зафіксований через `bind`, уже не замінити: `.call({ total: 50 })` на зв'язаній функції все одно
   дає 40.

Висновок: на відміну від варіанта з аргументом, тут кожен виклик бачить своє `total`, бо кожен отримує власний
об'єкт.

Межові випадки:

- Звичайний виклик `show()` у нестрогому режимі отримує `this = globalThis`, і `with` шукає `total` серед
  глобальних властивостей. Якщо такої немає, вийде 10. Якщо ж на верхньому рівні звичайного скрипту стоїть
  `var total = 99`, вона стає глобальною властивістю, і `show()` надрукує 99. У файлі-модулі `var` верхнього
  рівня глобальною властивістю не стає.
- У пісочниці звичайний `show()` друкує в консоль браузера, а не на сторінку: `with (window)` знаходить справжні
  `setTimeout` і `console` раніше за підставні.
- Якби повернута функція була стрілковою, `call`, `apply` і `bind` не змогли б змінити її `this`: стрілкова
  функція бере `this` з виклику `makeShower`.

## Геттер і сетер

Змінну замикання ззовні не видно: ні прочитати, ні змінити її синтаксисом мови не можна. Доступ мають лише функції,
створені в тому самому виклику, бо в них спільне оточення. Геттер і сетер - такі функції, оформлені як властивість
об'єкта. Двері до змінної відчиняє автор функції, і він вирішує, що через них можна.

```js
function makeShower(total) {
  return {
    show() {
      setTimeout(function () {
        console.log("знімок:", total);
      }, 0);
    },
    get total() { return total; },
    set total(v) { total = v; },
  };
}
const shower = makeShower(10);
makeShower(20);
makeShower(30);
shower.show();
shower.total = 40;
console.log("зараз:", shower.total);
```

Вивід:

```
зараз: 40
знімок: 40
```

Чому так:

1. `makeShower` тепер повертає об'єкт із трьома функціями: метод `show`, геттер і сетер `total`. Усі три створено
   в одному виклику `makeShower(10)`, тож вони тримають одне оточення й одну змінну `total`.
2. `get total()` і `set total(v)` створюють властивість-аксесор. Ім'я `total` у них - ключ властивості, а не
   змінна. У тілі сетера ім'я `total` шукається за звичайними правилами: в оточенні самого сетера є лише `v`, тож
   пошук доходить до оточення виклику `makeShower(10)`.
3. `shower.total = 40` викликає сетер, і той присвоює 40 саме змінній замикання. Змінна справді змінюється, а не
   перекривається, як у варіантах із `with`.
4. Рядок `зараз: 40` друкує геттер синхронно, ще під час скрипту. Колбек таймера спрацьовує після кінця скрипту,
   читає ту саму змінну й друкує `знімок: 40`.
5. `makeShower(20)` і `makeShower(30)` створюють окремі замикання, і сетер `shower` їх не зачіпає.

Висновок: результат той самий, що у варіанті з `total = next`, але інтерфейс чистіший і без `with`, тому код
працює і в strict mode, у модулях і класах.

Межові випадки:

- Лише сетер, без геттера: запис доходить до змінної замикання, а читання властивості дає `undefined`.

  ```js
  function makeBox() {
    var value = 0;
    return { set value(val) { value = val; } };
  }
  const box = makeBox();
  box.value = 5;   // у замиканні тепер 5
  box.value;       // undefined: геттера немає
  ```

- Параметр сетера з тим самим іменем: `set total(total) { total = total; }` нічого не змінює. Ім'я `total` тепер
  знаходиться вже в оточенні сетера, бо це його параметр, тож рядок присвоює параметр самому собі.
- `show` не використовує `this`, тому `const f = shower.show; f();` працює й відірваним від об'єкта. Якби метод
  читав `this.total`, такий виклик зламався б.
- `const { total } = shower` викликає геттер один раз і копіює число. Подальші зміни через сетер цю змінну не
  зачеплять.
- `{ ...shower }` викликає геттер і кладе в копію звичайну властивість-значення. Запис у копію змінює лише копію,
  замикання оригіналу його не бачить.
- Запис у властивість, яка має лише геттер: у strict mode - `TypeError`, у нестрогому режимі запис мовчки
  ігнорується.
- У сетері можна перевіряти значення перед записом, наприклад кидати `TypeError`, якщо прийшло не число.
  Звичайна властивість об'єкта такого не дає.

## Розділи специфікації

ECMA-262:

- 9.1.1.2 "Object Environment Records" - оточення-об'єкт для `with`; метод HasBinding перевіряє властивість і
  `@@unscopables`.
- 9.1.2.3 "NewObjectEnvironment" - створення оточення-об'єкта.
- 10.1.8.1 "OrdinaryGet" - читання властивості без геттера дає `undefined`.
- 10.1.9.2 "OrdinarySetWithOwnDescriptor" - запис у властивість без сетера не вдається (у strict mode - `TypeError`).
- 10.2.1.2 "OrdinaryCallBindThis" - звідки береться `this`, зокрема `globalThis` у нестрогому режимі.
